## 当前资源与加载

原 91,057,412 字节整栋 GLB 拆成 13 个空间模块：连续建筑核心、左右各三个侧区、A/B 两端、两组中央家具、灯具和地球仪。全套模块为 43,684,648 字节，最大单文件为 9,315,084 字节。11 张原始 PNG 共 6,410,857 字节，按内容哈希共享，没有重复解码成每个区域独立的纹理副本。

- `library-manifest.json`：模块地址、边界、优先级、精确大小和 SHA-256
- `materials.gltf`：全场景共享的材质、贴图和采样器
- `modules/*.glb`：KHR Meshopt 无损压缩后的空间模块
- `scene-config.json`：367 个碰撞描述、双楼梯路径及独立运行灯光

默认第一阶段的八个模块加共享贴图约 29.34 MB，之后继续加载其他细节。实际书目及阅读返回位置可能提前请求更多区域。完整几何和图片约 50.10 MB；这些是文件大小，不是实测加载时间。

所有 1,552,983 个三角形、逐角点 POSITION/NORMAL/UV 原始浮点字节、材质分配以及 11 张图片均与原模型完全一致。局部索引只在数值完全可表示时使用 Uint16。没有减面、浮点量化、三角形旋转或贴图重压缩。人物雕像、地球仪、护栏、木作和上层桌椅没有删除。

## 渲染策略与真实限制

模块同时最多进行两个加载任务。原始材质和 Three.js 派生材质变体共享同一对象，避免跨 GLTFLoader 解析生成重复 GPU 材质/贴图。

支持 `WEBGL_multi_draw` 的浏览器使用按材质组织的动态批次，保留分对象裁剪。兼容路径在全部模块就绪后，分批让出执行权并按材质整合，稳定状态恢复为 28 个建筑材质批次；整合后兼容路径保留全部建筑，不宣称细粒度卸载或内存节省。建筑统计不包含真实书模、分类牌及其他应用绘制。

静态阴影只在建筑、书籍或灯光实际变化后更新，相机移动可以复用阴影。当前方向光的阴影视野覆盖几乎整栋大厅，因此高精度阴影通常会让所有模块最终常驻；分文件不等于总渲染工作减少。完整模型仍有约 155 万三角形。现有渲染循环约 30 FPS 上限也不代表显卡能力。

CPU 检查验证了两种路径的 28 个建筑提交批次、资源共享与清理，并发现构建过程中仍可能出现长任务。浏览器 FPS、移动端、首次交互时间及实际 GPU 内存尚未验收。此前云浏览器 localhost 访问受到安全限制，没有绕过；Blender 渲染和单元测试不能替代这些结果。
