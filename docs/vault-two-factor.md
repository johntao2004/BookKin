# 禁书区身份验证器流程

禁书区默认关闭。主人在「管理设置 → 用户与权限 → 安全设置」开启，角色仍须具备 `vault.use` 权限。管理员只能查看该开关，主人也必须完成个人 2FA 验证才能访问内容。

首次进入时，用户输入当前登录密码，使用支持标准 TOTP 的身份验证器扫描本地生成的二维码，输入 6 位动态码完成绑定，下载并保存一次性备用码。二维码有效期 10 分钟。每次进入禁书区先撤销该会话的旧访问授权，然后验证动态码；设备遗失时可使用一条未使用的备用码。重新绑定必须同时验证登录密码和动态码或备用码，旧会话授权随之失效。

正常访问只输入一次 2FA 动态码，验证成功后直接浏览、阅读，不再显示二次密码或本机授权表单。内容密钥由服务器以独立用途的实例密钥加密保管，已验证会话通过禁止缓存的密钥接口领取；客户端只在当前页面内存中解密内容。

此模式由服务器管理内容密钥，不再是服务器无法解密的端到端模式；普通主人/管理员权限仍不能领取其他用户密钥。每次领取均验证用户、会话、2FA 与权限，页面退出时清除内存主密钥，不持久保存访问授权或明文密钥。

换浏览器或清除站点数据后仍通过 2FA 直接进入。空的旧书库可无损升级；有内容的旧书库只允许迁移已验证的原密钥，不生成替代密钥。迁移边界和备份要求见 [仅 2FA 进入设计](vault-two-factor-entry.md)。旧版离线恢复资料应继续保留。

服务端逐请求保护所有 `/vault/**` 配置、密文、分块和记录接口。2FA 授权绑定用户、登录会话、凭据版本与管理策略版本，单次租期 5 分钟；当前可见页面每分钟续期，续期只能延长尚未失效的现有授权，正常阅读无需反复验证。退出页面、隐藏标签页、主动锁定、到期或访问失败时，前端卸载解密内容并撤销授权；重新打开网站进入禁书区时先撤销旧授权，再显示 2FA 弹窗。正常登录 Cookie 可保留 30 天，但仍受主人配置的服务端会话最长时长限制，锁定禁书区不会退出登录。

重新验证会清除输入；二维码和 2FA 备用码不写浏览器持久存储。关闭功能保留密文，重新启用后旧授权失效。

验证码允许前后一个 30 秒时间窗；已成功使用的时间步不能再次验证。备用码只存按用户绑定的 SHA-256 摘要，原码仅在生成时返回。失败计数存 PostgreSQL，5 分钟内最多 8 次尝试，进程重启不能清除计数。绑定、验证、重绑与开关变更记录无秘密值的审计事件。

## 实例配置与备份

生产部署须通过私密环境变量配置 `BOOKKIN_TWO_FACTOR_ENCRYPTION_KEY`，建议使用至少 32 字节随机值。未配置时服务端拒绝启用，不能降级为明文存储。该密钥加密用户 TOTP 种子，并以独立用途派生内容密钥包装密钥；密文绑定用户，内容密钥同时绑定规范化信封。数据库不存实例密钥。

本地 `pnpm start:local` 自动生成并复用 `.local/two-factor-encryption-key`，目录被 Git 忽略，文件权限由 `umask 077` 保护。生产请使用秘密管理系统，并单独安全备份实例密钥；更换或丢失它会导致现有身份验证器设置及托管内容密钥不可读取。常规数据库备份不包含这一环境秘密。

算法与兼容性依据：[RFC 6238](https://www.rfc-editor.org/rfc/rfc6238.html)，SHA-1、6 位、30 秒；二维码采用标准 `otpauth://` URI，无需 SMTP 或第三方认证服务。
