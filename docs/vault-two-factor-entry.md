# 秘藏阁仅 2FA 进入

每次访问先经过普通登录、`vault.use` 权限与会话绑定的 2FA。通过后直接加载加密书库，不再要求二次密码、本机授权或恢复密钥。退出页面、标签隐藏、锁定、验证过期和权限失效仍会卸载内容并清除页面内存中的解密密钥。

`POST /api/v1/vault/key/open` 与 `/key/migrate` 受原有服务端 `VaultAccessConfiguration` 拦截器保护，响应禁止缓存。新内容密钥由服务端随机生成；V30 在 `personal_vault` 增加 `access_key_ciphertext`。密钥以 AES-256-GCM 包装，AAD 绑定用户和数据库规范化信封。包装密钥使用 `BOOKKIN_TWO_FACTOR_ENCRYPTION_KEY` 的独立域派生，与 TOTP 凭据的用途分离，不与数据库一同保存。客户端只在当前已验证页面的内存使用领取的内容密钥，不在浏览器持久保存明文密钥或访问授权。

这是服务器管理密钥的加密存储模式，服务器在授权后能够提供内容密钥，不再宣称服务器无法解密的端到端模式。生产环境使用 HTTPS，并将实例密钥和数据库、密文分开安全备份；丢失或任意替换实例密钥会使 TOTP 设置和已包装的内容密钥不可读。现有备份不包含实例密钥，必须另行保管。主人/管理员的普通管理权限不授予其他用户的密钥访问权。

空的旧版书库在行锁事务内升级，无任何文件改写。已有密文时严禁生成替代密钥：仍持有旧本机授权的浏览器可在 2FA 后自动迁移原密钥，服务端先验证已有书籍的 AES-GCM 清单，再包装原密钥，所有文件、阅读记录和信封保持不变。迁移提供 revision 冲突检查及相同密钥重试的幂等行为；旧客户端不得覆盖已托管的信封。

若非空旧库既未迁移、又没有任何仍持有原密钥的浏览器，则无法凭 2FA 从旧密文推导内容密钥。此情形保留原数据并明确报错，不删除、替换、跳过解密或伪装成空书库。历史离线恢复资料仍应保留，用于独立的旧数据恢复迁移；正常进入流程不显示密码表单。
