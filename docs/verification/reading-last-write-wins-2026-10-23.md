# 多标签页阅读状态保存

## 范围与实现

用户澄清：问题是两个标签页打开同一篇文章后，翻页保存提示另一页面已更新；要求所有阅读器统一采用最后提交的阅读状态。普通内容编辑、合集及设置的版本策略不在本次变更范围。

- 文章：移除 `article_reading` 更新的客户端 revision 条件。单条 PostgreSQL upsert 按用户与文章原子写入，服务端 revision 继续递增，旧客户端请求兼容。
- 禁书区：阅读密文状态采用同一规则；对象不存在或不属于当前用户返回 404。密钥信封的版本保护保持独立。
- 普通书籍：原有阅读位置 upsert 已采用相同规则，本次增加回归覆盖。
- 后提交的进度可以小于先提交的进度，允许回到前文；不比较客户端时钟，也不取最大进度。
- 同一标签页的保存继续串行执行；成功重试后清除先前的保存错误。
- 所有访问权限、用户数据隔离及大小限制继续执行。无数据库迁移，无用户已有阅读数据改写。
