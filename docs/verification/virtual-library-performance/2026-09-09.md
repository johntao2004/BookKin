# Long Room runtime performance investigation

Local authenticated `/virtual-library`, four real books, enlarged Long Room. Observations are browser samples on this machine, not controlled benchmark averages or GPU timings.

| Observation | Before | After |
| --- | --- | --- |
| Synchronous world construction | 2270.8 ms | 2090.6 ms |
| CPU time around render submission, sampled warm frame | 7.5 ms | 3.1 ms |
| Draw calls (instrumented intermediate direct-render build, then auxiliary material fix) | 342 | 56 |
| Renderer geometry resources | 309 | 201 |
| Renderer texture resources | 16 with composer | 3 at idle hall |
| Idle behavior | continuous frames | repeated reads remained at 23 frames |

Changes: remove legacy bloom/composer passes for the daylight hall; preserve the former composer effective pixel ratio of 1; share window and marble materials so static batching combines them; skip rendering invisible hit materials and fully faded selection overlays; compile shaders asynchronously; redraw on camera/book/hover changes, texture completion, resize and visibility restoration; wait for camera and inspected-book transforms to converge before idling. Texture loading uses a scene-owned LoadingManager. Avoid creating three procedural wood textures immediately replaced by the packaged oak texture.

The RAF callback still checks a small state signature; the expensive animation/collision/scene traversal and WebGL work stop while idle. This is render-on-change, not a claim of zero browser CPU usage. A cold synchronous shader/first-render sample reached 9628.9 ms in an intermediate build; after compileAsync, one compile sample was 310.5 ms, but driver caches and machine load differ, so those are not a reliable speedup ratio.

Remaining bottlenecks: synchronous parameterized construction still costs about two seconds and visible rendering submits roughly 6.4 million triangles. Offline model baking/progressive loading and spatial LOD for distant decorative books remain future work. Real catalog books and their picking geometry remain intact.

Final additional batching: the harp's 29 separate string lines now share one LineSegments draw, preserving all segments. A fresh hall sample after this change reported 28 draw calls, 173 geometry resources, 3 textures, 1.2 ms CPU render submission, 1661.1 ms world construction and 116.1 ms asynchronous shader compilation. These remain single-run observations. Browser verification covered idle frame stability, resuming on My Books, fully converged shelf focus and selecting a real book into inspection mode followed by idling again.

Validation: final lint, TypeScript and build passed. Full suite: 227 passed, 4 failed across non-scene components. Follow-up run containing the virtual-library page, scene, Long Room and the four failed files: 57 passed, 2 failed. All three virtual-library test files passed; password-policy and BooklistDetailPage still failed. AppShell and RecentAnnotationsPanel passed on rerun. These failures have not been attributed to or fixed by this scene-only performance change.

## Progressive construction follow-up

Construction now yields between alcoves, gallery setup, individual vault ribs, instanced-band buffer chunks, geometry-clone chunks and static batches. The synchronous entry points remain available for offline generation and existing tests. An AbortController cancels construction on route exit or effect replacement; a timer-driven cancellation regression test verifies that queued navigation gets an opportunity to run after the first stage. The loading indicator remains visible until the first rendered frame.

Historical volumes now write transforms and colors into growable typed buffers instead of allocating Matrix4, Quaternion, Vector3 and Color objects per volume. The band buffers are filled in chunks and InstancedMesh buffers are allocated without the unused identity-matrix initialization pass. Long Room construction skips unused legacy stone/rug texture generation. Geometry detail and the 29-string harp are preserved.

Final browser sample after a transient local API restart recovered: 2521.9 ms overall construction elapsed (includes intentional yields), longest construction/batching slice 203.6 ms, synchronous integration 184.2 ms, 28 draws and 6,428,834 triangles. This improves responsiveness relative to one uninterrupted approximately two-second world build; it does not claim lower total loading time or elimination of all long tasks. A previous intermediate sample still had 350–539 ms stages, which drove the additional subdivision. Further work can reduce individual large merge batches and move offline geometry generation out of the browser.

Follow-up final validation: lint, TypeScript and build passed; the virtual-library page, scene and Long Room suites passed all 45 tests including construction cancellation. Browser check retained all four actual catalog books, 40 shelf sections and 90 colliders, and My Books still focused the real shelf and stopped rendering once settled. The previously recorded unrelated full-suite failures were not changed in this follow-up.
