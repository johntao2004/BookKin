# 本地主要流程验收 — 2026-10-23

本轮在真实本地 API、Worker、PostgreSQL 与浏览器中检查上传、下载、阅读、文章合集、秘藏阁和角色权限。起点为 `b6ad721`。预览为 `http://127.0.0.1:4176`；API/Worker 经 `pnpm start:preview` 调用 `pnpm start:local`，使用 `.local/run` 下的不可变 JAR。没有部署生产环境。

## 发现与修复

1. **DeepSeek 结构化提取可能没有最终答案。** 真实 PDF 请求使用默认思考模式时，4096 个输出 token 全部消耗在思考中，`finish_reason=length` 且正文为空。官方 DeepSeek API 的书目匹配和知识提取请求现显式发送 `thinking.type=disabled`；其他兼容平台不增加此参数。截断响应即使包含可解析 JSON 也拒绝接收。原文证据、权限、指纹和人工审核边界保持生效。协议依据：[DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)。
2. **书籍详情缺少实际下载入口。** 新增共享样式的“下载原书”链接，仅对有 `reader.read` 权限且文件可用的登录用户显示；复用受权限控制、流式传输的原文件接口。浏览器已实际下载 EPUB 和 PDF，两个文件的 SHA-256 均与上传源文件一致。
3. **可选数据库测试引用已删除的 V20 迁移。** 迁移已合并为 V1，原测试默认被环境条件跳过，无法发现引用失效。本轮改为验证缺少旧设置字段时的读取默认值，以及主人开关在服务实例之间的真实持久化，移除对历史迁移资源的依赖。数据库持久化测试在独立测试库中补跑通过。

## 已检查的用户流程

- 管理员和两名成员实际认证并读取各自有效权限；成员经用户管理 API 创建，完成临时密码首次改密。独立管理员初始夹具使用新用户行建立，随后通过主人角色 API 验证管理员/成员转换。
- 管理员降级后，同一已有会话立即失去管理 API 权限；恢复后同一会话恢复访问。成员文章权限撤销后立即返回 403，最后恢复原授权集合。主人不可自行降级，管理员和成员均不可配置主人专属权限。
- 停用账号的已有会话与新登录均被拒绝；浏览器也实际验证管理员、成员、停用及匿名身份。成员直达编辑/用户管理地址显示 403；管理员直达角色配置显示 403；匿名访问合集显示 401。
- EPUB、PDF 经创建暂存、流式上传、解析、元数据确认和提交入库；重复 SHA-256 被识别为重复，幂等提交返回原书籍。成员上传、改书目和预览 NAS 写操作被拒绝。
- 校对书名、副标题、作者、译者、语言、出版社、日期、ISBN 清空、系列/序号、标签、具体 Thema 分类、简介、作者介绍、目录和公开状态。保存后重新读取确认；空 ISBN 按接口约定归一为 null。最终案例归回适合内容的字段和分类。
- 浏览器走完普通上传、保存草稿后刷新、封面 2:3 裁切、确认入库、已有书目编辑、EPUB 翻页和目录、书签定位与刷新恢复，以及 PDF 正文、翻页、书签。四本源文件在 API 重启后仍可完整下载。
- 文章重复内容被拒绝；浏览器编辑文章 Markdown、标签及封面并保存，再从 API 确认持久化。共享/私人合集创建、文章加入、排序、重复成员拒绝、说明编辑正常；其他用户不能编辑共享合集，管理员不能读取别人的私人合集。
- 普通书籍和文章阅读状态按最后成功提交生效，阅读位置和批注按用户隔离。实际阅读留下的书签和札记继续保留。
- 两名成员分别通过 TOTP 绑定并打开秘藏阁，无第二次解密密码；各自加密上传、解密下载哈希校验、密文分块幂等与禁止覆盖、状态保存、跨用户隔离均通过。新普通会话仍需独立二次验证，锁定后不能通过续期重新打开，备用码只能使用一次。
- 浏览器另走完秘藏阁动态码、客户端加密上传、实际解密阅读、独立笔记与书签保存/复开、锁定隐藏内容，以及 32 位备用码整段小写粘贴和显式提交。结束时已锁定秘藏阁。
- DeepSeek 模型目录经认证实时读取，使用 `deepseek-flash`。只启用 DeepSeek，关闭自动匹配；书目建议保留人工审核，未自动采纳。编辑后的文章又基于新正文重新分析。模型密钥由应用加密保存，API 设置读取不返回明文。
- 受检页面控制台没有未处理异常。修复重启时出现预期连接错误页，服务恢复后自动回到原文章阅读页。
