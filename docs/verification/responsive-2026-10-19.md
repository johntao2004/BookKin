# 多屏响应式验收记录（2026-10-19）

## 范围与变更

本轮针对页面放大、窄屏导航拥挤与移动端适配缺失，修复共享页面和控件。保留工作区原有大屏网格、全宽内容区及普通页面比例策略。

- 导航在 1024 CSS px 以下使用抽屉；搜索、主题、账户按原顺序排列，点击区域为 44px。窄屏搜索展开后自动聚焦，输入区域保持在屏幕内。
- 手机页面标题、空状态及概览文字使用较小的现有字号 Token；标题、工具栏、日期和统计内容允许换行，书名最多展示三行。
- 移除 body 的 320px 最小宽度，避免滚动条占宽后产生页面溢出。
- 共享表格容器允许内部横向滚动；浮层使用页面逻辑视口限制边界。
- 弹窗直接限制 Ant Design 实际容器的高度，正文独立滚动，标题与底部操作保持可见。浏览器发现 `ant-modal-render` 中间层会截断 `max-height: inherit`，因此容器使用显式逻辑视口计算。
- 修复样式适配器将 `WebkitLineClamp` 数值错误转换为 px 的问题。

第一阶段没有修改设计 Token，也没有修改阅读器和 3D 场景的布局。用户随后将范围扩大到全站，第二阶段结果见下文。

## 第二阶段：全站、阅读器与虚拟书库

按新增要求检查全部路由及其共享布局，包括登录、注册、初始化、找回/重置密码、个人资料、改密、首页、藏书库、分类/详情、书单/详情、阅读笔记、展示书目、上传校对、回收站、设置四分区、用户/操作日志/登录日志/安全设置、错误页、EPUB/PDF 阅读器和虚拟书库。旧管理地址沿现有重定向进入对应分区。

修复内容：

- `AuthFrame` 在手机、平板、短横屏保持表单可滚动；宽屏分栏从 1024px 开始，表单保持可读宽度。个人资料、安全设置及创建用户弹窗同步适配。
- 共享 Drawer/Dialog 的响应式 `sx` 改为生成媒体规则，避免把断点对象作为无效内联样式。菜单浮层也使用样式编译器。详情操作允许换行，书单/展示书目手机整理操作独占一行。
- 阅读器跟随 `visualViewport` 可见高度，以实际阅读表面宽度决定单/双页；外框仍为全宽固定边距，内部正文限制每列宽度。手机将目录、书签和笔记收进“更多阅读操作”，保留阅读设置及 44px 点击区。
- PDF/演示文本只在虚拟页父容器裁切，平移文章自身保持 `overflow: visible`，防止翻到后续虚拟页后正文消失。EPUB 底部独立翻页栏取代遮盖正文的悬浮箭头。
- 虚拟书库增加容器尺寸监听、动态视口高度、短横屏布局和双指缩放；限制 WebGL backing store 的像素预算。紧凑视口默认收起控制面板，保留搜索/展开入口；选书预览按视口放大并保留原比例，书名阅读入口至少 44px 高。
