# 新增文章重复检测

## 行为

- 抓取前检查来源链接，抓取重定向后的最终链接也检查；重复时返回 HTTP 409 / `ARTICLE_DUPLICATE`，不进入导入预览。
- 保存时同时检查来源和正文。链接忽略片段、常见追踪参数及微信公众号分享参数，保留一般网站的业务参数；同标题不同正文可正常保存。
- 正文比较忽略排版和多余空白，图片按本地文件的 SHA-256 比较，重新抓取产生的新资源 ID 不影响判断；空正文不作为重复依据。
- 编辑排除自身；事务锁覆盖查重和写入，防止并发保存重复记录。
- V27 只增加检索字段和索引，不删除或合并旧文章；旧记录在保存事务内补齐检索字段。
- 重复提示沿用抽屉的错误展示，保留链接和草稿供修改。

## 验证

- `pnpm lint`、`pnpm typecheck`、`pnpm build` 通过。
- `ArticlesPage.test.tsx`：13 项通过，包含重复链接提示和重复正文拒绝后修正重试。
- 前端全量：771 项通过、2 项失败（分类空态、禁书区锁定异步响应）；这两个测试文件单独重跑 14 项全部通过。首轮全量结果未记为通过。
- 启用本机 PostgreSQL 原生测试的 `./mvnw verify` 通过：241 项，0 失败，9 跳过。原生查重测试覆盖 V26→V27 历史重复保留、旧正文查重、链接变体、编辑自身、编辑冲突和并发保存仅一条成功。
- 本地浏览器 `/articles` 实测：已有微信链接加分享参数被拦截；手动导入旧文章相同正文被拦截；草稿保留；控制台错误为空；集合仍为原有 2 篇。
