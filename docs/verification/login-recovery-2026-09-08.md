# 本地登录与会话恢复排查（2026-09-08）

## 复现与根因

- `无法建立安全会话`：前端仍在运行，但 API 8080 未监听，Vite 代理的 CSRF 请求返回 502。
- `Failed to fetch`：API 健康检查正常，但前端 4173 未监听。浏览器仍显示已加载的旧登录页。
- 原 `pnpm start:local`、`pnpm dev` 为前台命令，生命周期依赖调用终端。原后端就绪等待只有约 30 秒；本次高负载下 JVM 启动约 47 秒，复现脚本主动终止刚启动的服务。
- `getSession()` 原先吞掉全部错误，网络故障会被当作未登录；认证请求没有超时，网络异常文本直接冒泡到 UI。
- 会话初始化的迟到结果可能覆盖已经完成的登录。真实环境原先也读取、写入演示身份缓存；切换身份没有统一清空查询缓存。

## 修复

- 新增 `pnpm start:preview`、`pnpm status:preview`、`pnpm stop:preview`。新进程脱离终端，日志和 PID 保存在 `.local/`；复用健康服务，等待 API 与前端 CSRF 代理就绪。停止操作只处理该入口记录且命令身份匹配的进程组。
- 后端仍通过 `pnpm start:local` 创建并运行不可变 JAR 快照。就绪等待延长至约 120 秒。
- 认证请求 15 秒超时，区分断网、服务端不可用、凭据错误；网络失败不会自动重放登录或密码修改请求。保留一次 CSRF 刷新重试。
- 未登录的受保护请求明确返回 401；保持 CSRF、防会话固定、角色权限和强制改密保护。
- 仅 401 会话查询结果表示未登录。其他故障展示“重试连接”，不挂载私有页面。迟到初始化结果不能覆盖新登录。
- 真实身份不再依赖演示 sessionStorage；切换身份清理查询缓存；服务端报告会话过期时同步清理前端身份。退出失败显示可理解的错误，已过期的会话允许退出。

## 实际验证

- 通过真实 Vite 代理与 PostgreSQL，用随机临时 MEMBER 测试账户完成：匿名会话 401、无 CSRF 登录被拒、错误密码被拒、临时密码登录、会话查询、强制改密阻断私有 API、修改密码、私有 API 访问、退出、旧密码失效、新密码重新登录。测试账户、会话和测试审计行已清理。
- 新入口启动完成后退出调用进程，再执行启动与状态查询，确认 API、前端继续可用，重复启动复用现有服务。
- 浏览器在后端与前端重启后刷新，owner 仍进入强制改密页，控制台无错误；未替用户填写或提交新密码。
- `./mvnw verify`：76 项，0 失败，4 项依赖 Docker 的测试跳过。本轮没有据此宣称 Docker 集成验证完成。

- 前端 Lint、TypeScript 与生产构建通过；完整测试最终 60 个文件、220 项通过。机器高负载下默认并发运行曾出现无关用例超时，最终使用 `pnpm --filter @bookkin/web exec vitest run --maxWorkers=1 --testTimeout=60000` 完成全量复测（523 秒）。产品认证请求超时仍为 15 秒。
- 最终 `pnpm status:preview` 确认 API 和前端 CSRF 代理均 ready；两个启动进程的父进程均为 1，已脱离调用终端。

## 边界

后台启动入口不安装系统服务，不承诺重启电脑后自动启动，也不屏蔽真正的服务或网络故障。服务不可用时仍应保留错误和重试入口，不能伪造成功会话。owner 仍需亲自完成临时密码后的新密码设置。
