# AI 功能覆盖与验收（2026-10-23）

本轮将原先集中在书目匹配、知识点提取的 AI 能力扩展到阅读、合集及编辑流程。真实请求使用本地已加密保存的 DeepSeek 配置，模型为 `deepseek-flash`。密钥、账号密码、会话、TOTP 和本地配置均未进入本目录或 Git。

## 覆盖清单

| 入口 | 本轮新增能力 | 权限与采用方式 |
| --- | --- | --- |
| 书籍详情 | 摘要、结构提纲、讨论问题、原文问答 | `reader.read`；服务端读取受管原文，只返回建议 |
| EPUB / PDF 阅读器 | 同一组 AI 助读功能 | 复用文件租约、路径及指纹校验；不读取个人进度或其他用户批注 |
| 文章阅读器 | 摘要、提纲、讨论问题、原文问答 | `articles.view` 并检查文章可见性 |
| 文章合集 | 阅读顺序与导读、摘要、讨论问题、问答 | 只读取当前用户可访问的合集及文章 |
| 上传校对 | 简介与标签建议 | 上传或元数据编辑权限；预览后采用，再保存草稿或确认入库 |
| 已入库书籍元数据 | 简介与标签建议 | `library.edit`；不改作者、ISBN、出版事实或人工学科分类 |
| 文章 Markdown 编辑器 | 润色、提纲、标题建议、摘要 | `articles.edit`；只有润色支持直接采用到当前草稿 |
| 个人短笔记及书籍 / 文章博文 | 润色、提纲、标题建议、摘要 | `notes.edit`；仅发送明确确认的当前草稿，仍经原保存流程提交 |
| AI 管理设置 | 真实连接及结构化响应检测 | `settings.ai.edit`；仅测试已保存配置，不提交未保存表单，也不发送私人内容 |

既有书目匹配与书籍 / 文章知识点提取继续工作。本轮上传匹配返回了 DeepSeek 候选并明确提示需复核；未用候选覆盖人工草稿。新书正文生成了 10 个有原文依据的知识点，文章生成了 4 个。

## 数据发送及结果边界

- 每次打开助手均重新确认发送；打开页面、展开对话框不会自动调用模型。
- 书籍 / 文章最多发送 12 段采样，每段 1800 字；合集最多前 6 篇可见文章，每篇 3000 字；草稿上限 20000 字，超出时明确阻止而非静默截断。
- 原文摘录必须匹配服务端采样中的真实连续文本及位置；没有有效依据时，阅读回答改为“材料不足”。采样范围、平台、模型均持续显示，不能理解为全文分析或事实保证。
- 请求前后复查当前角色权限、对象可见性和源内容；原文发生变化则丢弃结果。每个用户同时最多一个助手请求，并有 3 秒间隔控制。
- 结果不进入共享缓存或数据库。关闭、换用户、换内容时清理；关闭会取消浏览器等待。草稿变化后不能采用旧结果。
- 结果复用经过清理的 Markdown 渲染，不执行脚本，不自动加载模型输出的远程图片。复制和采用保留 Markdown 文本。
- 原有 `MANUAL` 边界、独立阅读数据、原文件写回预览及幂等流程继续有效；模型没有工具执行权限。
- 秘藏阁解密正文、认证器、角色授权及 NAS 文件操作不交给外部 AI；没有引入 OCR、自动移动 / 删除或全量全文索引。

| 既有 AI 回归 | 上传书目匹配、普通书籍及文章知识点提取成功 |
| 浏览器 | 书籍助读、文章问答、合集导读、上传标签、元数据简介、博文写作、短笔记整理、连接检测及文章编辑入口实际操作 |
| 手机视口 | 390 × 844：短笔记生成、采用、保存成功；页面宽度与内容宽度均为 390，无横向溢出 |
| 持久化与隔离 | AI 标签与简介正常保存；原书下载 SHA-256 与上传源一致；成员私人博文对主人、管理员、其他成员均不可见 |
